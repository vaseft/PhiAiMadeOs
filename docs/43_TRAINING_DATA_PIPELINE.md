# 训练解析缓存与有界CPU准备

## 原因与范围

全库换源后，GPU低占用的现场处于CPU索引阶段。worker实测约占用1个CPU核心；模型尚未加载到CUDA，所以整卡5%及约1.9GiB占用不能用于判断训练计算时的吞吐。训练/验证共有325份谱面（保留集31份不参与索引），转换JSON合计约5.14GiB。

保持现有192维小模型、64线/320运动槽、有效批量16、8×2/预取1和数据/拆分不变。本次重点是减少CPU重复工作，沿用[PyTorch性能指南](https://docs.pytorch.org/tutorials/recipes/recipes/tuning_guide.html)关于改善供数、减少等待的方向；没有增加占位张量或扩大模型来制造显存占用。

## 实现

- `_training_cache.py`将完整数值投影保存到被忽略的`data/training_cache/projections/`。键绑定原谱文件SHA、特征SHA、条件、线容量及解析/投影/几何/模型/缓存实现SHA；每次访问重新核对源文件SHA。命中不缓存或替代授权检查，read_manifest仍先执行授权/对齐/分组门禁。
- 安全JSON与gzip保存，无pickle；解压上限256MiB，身份/内容payload SHA不符或损坏时回源解析。工件名含键和内容SHA，写入原子替换并对Windows短暂占用有界重试；旧版本工件保留，不删除训练审计引用。
- 特征仍以NPY mmap读取，只在内存保留当前谱面；事件轨道与时间索引从原值重建，不裁事件、音符、线或时间精度。新的训练清单用摘要及工件路径/解压后payload SHA引用完整投影操作，避免全库反复重写大清单。
- `build_windows`最多两路CPU进程、最多两个在途任务，不加载torch/CUDA；根据内存余量及最大原谱大小选择1或2路。任务完成顺序可不同，返回窗口按manifest顺序重组，并传回实际验证的文件SHA，维持数据和拆分指纹。
- 窗口显示“CPU准备训练窗口 X/325：缓存H份，新解析M份，N路准备”。索引可请求暂停，当前原子谱面工作完成后退出；已写缓存保留。完成CPU准备后关闭进程池，再进入GPU训练。

## 实际测量及边界

3份不同规模的真实train谱面，源/特征哈希与许可沿用已登记全库：

| 音符/投影事件 | 窗口数 | 冷解析含写入 | 缓存读取 |
|---|---:|---:|---:|
| 729 / 17775 | 87 | 1.386秒 | 0.066秒 |
| 1300 / 56026 | 254 | 3.870秒 | 0.196秒 |
| 785 / 114656 | 533 | 7.865秒 | 0.401秒 |

合计13.121秒→0.663秒，解析复用约19.8倍；完整投影canonical SHA一致，串/双路窗口边界与顺序一致。测量只做真实数据准备，没有执行额外训练轮次、打开保留集标签或修改模型权重。缓存命中不能替代全库错误恢复/长时资源和模型质量验收。

本次改动3份Python源码AST解析和提交前安全检查完成，既有CI单独报告。没有新增专项自动测试；新流水线的完整全库epoch、持续GPU利用率/显存峰值、缓存损坏/跨平台/暂停专项验收仍 **NOT RUN**。冷缓存首次处理仍需CPU工作，不保证把GPU或8GiB显存占满。

为部署先请求暂停，确认旧任务仍在indexing、无新run manifest/优化器更新后，仅终止对应解析worker，保留父模型和待执行换源请求；更新后从同一请求重新准备。模型与数据版本不重置。代码回退用revert；缓存可以保留，旧代码忽略它，新实现变更会生成新的SHA键。完整审计工件不随意删除。
