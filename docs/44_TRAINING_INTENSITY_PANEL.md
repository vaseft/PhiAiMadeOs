# 本地训练强度面板

入口：桌面 `PAMOs训练.cmd` → `http://127.0.0.1:8765/trainer.html`。本页与完整工作台共用数据、断点及任务队列。

## 可调整参数

| 参数 | 可选范围 | 实际作用 |
| --- | --- | --- |
| GPU并行窗口 | 1 / 2 / 4 / 8 / 16 / 32 / 64 / 128 | 单次前向/反向最多同歌曲窗口数；歌曲边界或最后一批会更小 |
| 梯度累积 | 1..128，总有效窗口不超过2048 | 有效批量=并行窗口×累积；改变每次参数更新的数据量 |
| CPU准备 | 自动或1..8路 | 初始索引使用进程池；按空闲内存、最大谱面体积估算实际可用路数，面板显示实际值 |
| CPU预取 | 开/关 | 提前准备下一批CPU张量，不预分配虚假GPU工作量 |
| 训练显存预算 | 2..7.2 GiB | 检查PyTorch峰值reserved，超限停止；不是显存占用目标，也不能保证OOM前触发 |

预设只填写表单，点击“保存强度设置”或“应用并继续训练”才写入本机 `.local/training-runtime.json`。稳健8×2/CPU2/6.2GiB；增强32×1/CPU4/6.6GiB；高负载64×1/CPU6/7GiB；极限128×1/CPU8/7.2GiB。预设名称仅代表请求强度，未经该硬件实测不能保证吞吐更快或显存可容纳。

实时GPU利用率、总显存占用、温度、功耗来自本机 `nvidia-smi`，缓存3秒，超时1.5秒；读取失败显示不可读。总显存包含桌面及其他程序，和单训练进程的reserved预算不同。CPU解析时GPU空闲属于真实状态。

## 生效与恢复

- 运行时保存：记录待应用意图 → 请求协作暂停 → 保存完整断点 → 等旧worker退出并释放GPU锁 → 使用新设置继续当前轮。暂停发生在CPU索引时，已完成投影缓存保留，当前在途谱面原子处理完成后退出。
- 已暂停或空闲时保存：只保存设置，点击“训练”才启动。打开网页不会启动训练。
- 点击“暂停训练”：关闭自动继续，并取消强度调整所安排的自动恢复。仅保存设置不会打开自动继续。
- 保留自动换源、已有来源链、数据拆分、权重/优化器/随机状态和窗口顺序；不上传音乐、谱面、权重或本地状态。
- 有效批量变化必须显式传入 `allow_effective_batch_change=true`；简洁面板仅对用户保存的设置发出此标志。普通API调用仍需明确授权标志。批量变化影响优化过程，不声称与旧训练轨迹相同。
- 真实优化器步数累计保留，学习率调度的位置按照已完成epoch与当前窗口游标重算，避免改批量后直接套用旧优化器步数。前后配置及哈希记录在 `resume_history`，恢复前按原有机制保存本机快照。
- OOM/预算失败停止自动继续；降低强度后从最近完整断点重试，可能重算最近一次保存后的窗口。UI没有承诺满载、性能提升或模型效果提升。

CPU索引调度新增 `_training_index.py`；原投影与缓存实现文件未改动，已生成的SHA绑定缓存继续可用。CPU内存估算按最大谱面字节×24+256MiB/路、保留约1GiB系统余量；这只是调度估算，训练worker仍有原6GiB RSS工程预算。

## 验证边界与回滚

本次按用户“测试以外”的要求，执行前端类型检查/生产构建、Python语法、现有服务只读状态和浏览器面板显示检查；新增设置保存/运行中调批量恢复、自动测试、32/64/128窗口GPU容量/吞吐对比均 **NOT RUN**，不宣称新参数已完成训练验收。现有GitHub CI结果另行报告。

部署时实际服务处于暂停状态。自动审批拦截了关闭旧服务并重启的操作，只返回“被策略阻止”，没有执行进程终止；新前端显示服务待更新，并禁用尚未生效的强度控件。需要完成经明确确认的工作台重启后加载新接口，不能将源码/构建完成表述为运行服务已经部署完成。

默认保留之前8×2、预取1的本机校准值；部署时若已暂停，不自行启动训练。回退使用 `git revert` 撤回本功能提交；在旧版续训前恢复原有效批量16的本机设置，使用本机训练快照选择兼容断点。原先谱面、数据、权重不在Git回滚范围内。
