# PAMOs 本地工作台 alpha

代码位于 `src/phiaimadeos/`、`web/` 与 `extensions/rpe-next-bridge/`。这是新实现，用户本轮要求不进行测试；所有新流程、模型能力和客户端兼容性仍为 **NOT RUN**。前端生产构建和依赖安装不等于功能验收。

## Windows 启动

已部署目录：`E:\PhiAiMade`。双击 `Start-PAMOs.cmd`，等待终端显示启动完成后打开 `http://127.0.0.1:8765`。终端按 Ctrl+C 结束，运行中的任务会取消并保留已写入的检查点。它只监听本机；单工作台实例、单 GPU 作业锁，长任务在独立 Python 进程执行。不要另起多 worker 服务。

界面或依赖需要恢复时运行 `Install-PAMOs.cmd`。脚本使用已有 `.venv` 和 `.tools/uv` 安装本项目，再在 `web/` 执行 `npm ci`、生产构建，不执行测试。全新机器需先按 [Windows 环境文档](34_WINDOWS_ENVIRONMENT.md) 安装 Python/CUDA/FFmpeg。默认使用原生 Windows，不依赖尚未安装的 WSL 发行版。

## 从授权音乐到导出

用户已准备好的原生谱面批量包可按 [本地谱面库导入](37_LOCAL_LIBRARY_IMPORT.md) 处理；该管理入口会在本机提取并关联音乐、曲绘和原谱。下面的单文件网页上传入口仍只读共同 RPE 结构并登记包内媒体引用。

1. 在“素材库”上传音乐，分别选择本机创作、训练、分发权限。原始文件本机保存，上传不表示训练授权。外部音乐不自动下载。
2. 上传 JSON、PEZ 或 ZIP 谱面时选择模式、难度，并关联单独上传的音乐。包内媒体会登记引用和告警，**不会自动导入音频/曲绘**。未知原始字段保留；不支持的依赖、扩展事件和噪域明确报告，无法完整携带的资源拒绝打包。原始上传文件不覆盖。
3. 音频“分析”提取传统 CPU DSP：25Hz/104 维磁盘特征、波形、起音、节拍候选、RMS/静音与置信证据。BPM 半速/倍速、变速和 offset 必须人工确认；没有足够证据会报错或明确警告。
4. “生成”选择歌曲、难度和模式。没有可用权重时只有 **规则基线（未训练）**，条件影响确定性规则。纯配置后端强制静线与固定 4/5/6K；常规允许有限线演出。异像缺少目标客户端能力证据，当前关闭，噪域不生成。
5. 候选自动进入独立非 AI 审计。BLOCK 是确定性阻断，WARN 表示需人工判断；PASS 只代表当前规则没有发现问题。模型 loss 不是可玩性评分，审计也不自动删音符或纠正 offset。
6. 在“审核”用原音乐时钟查看参考预览、拖动/暂停/选中音符、定位问题并标注。当前 Canvas 不是 Phira 渲染器；复杂扩展、透视/控制曲线、资源效果和某些父线语义需要客户端复核。
7. 真人填写六项评分（25/25/20/15/10/5）及审核人；内容哈希绑定该次判断。通过当前审计与人工审核后才可导出 ZIP。下载原 JSON 草稿允许未审核状态，文件名带状态。
8. ZIP 使用共同 RPE JSON、`info.yml`、音乐及程序绘制的默认曲绘。不调用图像 API、不自带受限曲绘。AAC/M4A 需 FFmpeg 解码成新的 FLAC 再打包，记录原/导出音乐哈希。分发导出要求所有来源明确允许 distribution。

## 局部修改和回滚

时间、类型、横向位置与固定列调整先创建提案，展示前后差异和独立审计。每次最多 12 个操作、16 拍窗口，音符/尾部移时上限 ±1/8 拍；不允许任意 JSON Patch、BPM/offset、模式或噪域修改。固定 K 禁止线运动。

提案绑定源哈希与预览哈希，24 小时过期；人工点击批准后仍需单独提交。提交重算差异并核对哈希，只创建新候选，重新审计，不继承人工通过。回滚也创建新候选，保留父版本、审核与试玩历史。失败不覆盖源文件。

## 训练与模型

训练需要音乐与谱面分别明确授权 training、人工确认绑定及 offset 对齐、填写歌曲簇 `group_id`。同曲的难度、转码、剪辑和相似版本必须同组；精确同音频会进一步合并。**未实现自动近似音乐指纹去重**，不能把音频 SHA 当成对相似歌曲的识别。

数据集 manifest 记录源/特征哈希、标签和按组划分；没有独立 train/val 歌曲簇会明确拒绝训练。模型以 192 维小模型、短窗口、microbatch 1、默认累积 16、顺序分阶段加载实现。纯 K 不训练或加载 LineMotionNet。复杂样本不静默删音符，窗口无法容纳会报告拒绝/拆分要求。

训练记录存 `data/training/<run_id>/run_manifest.json`、`metrics.jsonl`、真实检查点。界面展示失败/中断及实际日志，支持相同数据和配置恢复，epoch 可按模型说明增加。取消时只保留已完成的原子检查点；刚开始尚无检查点时不能假装可恢复。所有真实权重默认 experimental；candidate/stable 还需要模型生成谱面的独立审计、人工通过与真实试玩记录，stable 要覆盖声明模式/K 数。参见 [模型 worker 说明](MODEL_WORKER.md)。

本轮没有训练；上一轮合成 GPU profile 不是新模型实机负载证据。不要把旧的 0.096GiB 峰值用于承诺本次模型显存。

## 可选外部 API

默认关闭。设置在进程内存中保存，API Key 不写数据库/日志/前端存储，退出后需重填。仅允许公开 HTTPS 地址，固定解析后的公开地址并检查 TLS，不跟随重定向、不继承代理凭据。输出限额 128..4096 tokens，不编造调用费用。

每次先明确同意，才发送局部匿名音符、模式/K、窗口、哈希、局部问题代码及编辑要求；不发音频、文件路径、曲名、完整曲库。可识别内容若由用户主动写进编辑要求，仍会随该要求发送。返回必须是白名单结构化建议，本地验证后等待人工批准，失败保留原候选。

## RPE Next 与 MCP

双击 `Open-RPE-Next.cmd` 打开锁定源码的本机编辑器（`http://127.0.0.1:4173`）。工作台下载模组，用户在编辑器导入、看源码并启用，然后粘贴工作台一次性配对码。模组不复制上游实现，只使用公开 API 1。

配对会读取实际编辑器快照并创建候选。只有这个快照在同一会话中的、已经人工通过的修订可回写。编辑器内容若改变会拒绝覆盖；提交使用公开 `commit()` 和 `save()`，只有当前内容符合已批准修订且保存完成、dirty=false 才返回 SAVED。失败交由用户检查保存/撤销，绝不把已排队当成已保存。本轮没有实际加载模组/配对，联通验收仍 NOT RUN。

可选 stdio MCP 配置样例见 `configs/workbench-mcp.example.json`，需先启动工作台。工具可读候选/片段、提交建议、看 diff、提交已经由工作台真人批准的提案；没有批准、打分、改许可、外传或训练工具。此实现与旧 `pamos_mcp.server` 离线原型独立保留。

## Phira-Pro 客户端

官方 Windows 发布包 `v0.8.2-pro.16` 以官方发布页 SHA-256 校验后准备在 `.tools/Phira-Pro/`；`Open-Phira-Pro.cmd` 是手动启动入口。本轮没有运行它。恢复使用 `.venv\Scripts\python.exe scripts\install_phira_client.py`，仅下载和解压，不运行客户端。

发布包的 commit 与 `configs/upstreams.lock.json` 锁定的源码参考不同；二者分别登记，不能把下载成功当成接口或可玩性认证。来源：[官方发布页](https://github.com/Phira-Pro/Phira-Pro/releases/tag/v0.8.2-pro.16)，清单 `configs/client-releases.lock.json`。

## 本机数据与备份

`data/`、`data/training/`、`models/registry/`、`runs/`、`.local/`、`.tools/`、`.venv/`、`.cache/`、`web/dist/` 和 `web/node_modules/` 均不进 Git。停止工作台和任务后，可备份完整 `data/`、本机权重和必要本机配置；SQLite 的 WAL/SHM 文件不能在运行时拆开复制。删除源码分支不等于删除本机作品。

会话 cookie + CSRF、Host/Origin 与本机地址限制用于防网页误调用。运行本机程序的用户仍是同一信任边界；它不是多用户服务或抵御本机恶意软件的隔离沙箱。不要将 8765 暴露到公网。
