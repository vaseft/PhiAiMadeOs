# 03｜模型结构、训练、评测与模型注册

> **RTX 5060 8GB + 16GB RAM 的具体规格优先查阅 `docs/09_RTX5060_8GB_DEPLOYMENT.md` 与 `docs/10_LOW_VRAM_TRAINING_BLUEPRINT.md`；本文件是通用研究设计，不可用更激进的设置覆盖 5060 安全配置。**

## 1. 原则
- 只用约 500 首不同歌曲启动，**不要训练从零开始的大型音乐基础模型**。
- 首选**冻结的预训练音乐/转录音频编码器** + 轻量事件模型；与传统 DSP 音乐特征并用。音频编码器属于生成模型训练层，**严禁进入非 AI 审计层**。
- 先比较最简单可玩的规则基线，再训练小模型；不要让无效的神经网络复杂度掩盖数据对齐问题。
- 数据扩增：允许不改变音符时刻的音量/EQ/轻微噪声变化；变速/移调仅在**同步变更真实谱面时刻、BPM 与 offset**且得到版权许可时使用。

## 2. 推荐分阶段生成模型（按真实数据实验迭代）

### M1: Audio features / Beat context
缓存每曲的波形、log-mel、onset strength、RMS、chroma、beat/downbeat candidates；预训练音乐编码器（选许可证、速度、功能兼容的 AMT encoder/MERT 类模型）做冻结特征。固定缓存版本、帧率、声道与采样率，保证训练与推理一致。

### M2: 全曲规划器（可先用非学习式）
输入整首段落粗特征，生成 section boundary、每 4/8 小节目标 Note 密度、难度强度、预期判定线数量/运动强度。第一代可用可解释的模板和统计先验，后续训练小型模型。全曲规划确保副歌/高潮/休止部分不会全曲均匀堆 Note。

### M3: Note Rhythm/Type 模型
音频条件下生成事件时间、Tap/Hold/Flick/Drag 类型、Hold 结束拍和双押分组，不在此步决定最终屏幕位置。方案 A：小型 Transformer decoder 预测稀疏事件序列，条件为音频特征、目标难度、局部段落规划；方案 B：beat-conditioned slot 预测 + residual time。必须允许网格外音符（例如复杂切分），不能把每个 onset 硬映射 Note。

### M4: 判定线结构+运动模型
预测线数（有上限）、父子有向无环关系和每条线的分段 `x/y/rotation/alpha/speed/easing` 事件。建议先用**从训练谱面自动提取的线运动原型库**（静止、交叉、同步移、转动、交替出现等）选型，再细化连续参数；之后可以升级到 Transformer/离散扩散等端到端事件生成。随机角度+乱动不视为成功。

### M5: Note 归属与位置模型 + 联合修复
基于 Note 时间/类型和 line trajectories 预测 `line_id`、`positionX`、`above`、`yOffset`、`speed` 等；在判定时刻与相邻时间窗口计算实际屏幕位置，避免高速跳跃、不可读重叠、Hold 过程冲突。输出可解释的修复补丁，不直接抹掉所有提示为异常的合法谱型。

### M6: 完整歌曲拼接
通过音乐小节切分/重叠上下文逐段生成、按唯一 beat/id 消重、把同一线运动事件在边界融合、避免不连续转角和未闭合 Hold。保证音频末尾、尾奏和空段可以留白。

## 3. 首次训练配置建议（仅起点）

| 项 | 建议实验起点 | 原因 |
|---|---|---|
| 模型 | 首版 Note 4 层、hidden 192、4 heads 的 audio-conditioned Transformer；Line/Placement 各3层，阶段顺序训练 | 8GB 显存可实验，规模最终以实测为准 |
| 音频编码器 | 冻结、离线预计算 | 节省显存和训练时间 |
| 样本窗口 | 4 小节中心 + 左右各1小节上下文，超长时拆窗 | 保留局部音乐结构 |
| 批量 | microbatch 1 + grad accumulation 16（依据真机 profile 才调整） | OOM 可退化 |
| 精度 | CUDA 支持时 bf16/fp16（检查数值稳定） | 显存限制 |
| 优化器 | AdamW，warmup + cosine 调度起步 | 基线 |
| 损失 | 事件类别 CE、时间残差/位置回归、线轨迹重建、拓扑合法性与配置约束辅助项 | 多任务 |
| 划分 | train 400 / val 50 / test 50 歌曲组 | 防音频泄漏 |
| 评测 | 曲目级指标+盲审试玩 | 不只看 loss |

不要为缺失授权的特定预训练模型编造下载路径；首次实现应允许“无预训练音频 encoder + DSP features”的真实 baseline 运行。

## 4. 实验顺序和消融

E0：规则生成谱面（可游玩基线）。
E1：只预测 Note time/type、判定线固定。
E2：增加难度和全曲密度规划。
E3：加入判定线原型选择 + 运动参数生成。
E4：Note 归属/局部位置预测并加入几何约束。
E5：联合训练或后处理修复。

对于每个实验记录运行环境、数据哈希、配置、随机种子、精度、真实训练时长、显存峰值、失败率。只允许根据 **val** 调参，最终 test 在模型冻结后运行；盲测不能反复拿 test 集调模型。

## 5. 目标指标（并非保证值）

**离线参考谱面指标**：事件容差匹配 Precision/Recall/F1（例如 ±30/50/80ms 三档）、note type accuracy、Hold 端点误差、每小节密度 MAE、判定线轨迹采样误差（位置/角度/透明度）、运动连续性、谱面包 round-trip 通过率。多种等价演出可能导致参考误差偏大，不能当作唯一产品质量标准。

**无参考新音乐指标**：谱面解析成功率、硬约束通过率、音画同步风险分布、几何风险计数、非 AI onset/节奏统计（不能等同好坏）、人工评分与真人试玩通过率。困难点：复杂演出无唯一地面真值，需要用户评价。

**发布/注册 checkpoint 门槛**：可加载、固定输入可复现、相同规则基线对比、模型没有崩塌（note 类型/线运动不都退化为常数）、真实短歌推理能整曲导出，并通过至少一次人工试玩；没有达标的权重标记为 `experimental`，不可作为默认稳定模型。

## 6. Checkpoint / 模型注册

```
models/registry/<model_id>/
  weights.safetensors          # 如框架支持；仅存权重，不存任意执行对象
  config.yaml
  feature_config.yaml
  tokenizer.json
  label_mapping.json
  metrics.json
  dataset_version.json
  model_card.md
  sha256.txt
```

加载时验证架构版本、IR 版本、音频缓存版本、最大窗口/上下文、权重 hash；拒绝来源不明的可执行 pickle checkpoint。支持 `resume`、`best` 与 `last`，支持 CPU 推理调试。候选谱面关联权重 hash、采样温度、seed、生成耗时和所有后处理配置。

## 7. 反馈学习

人工评分与逐秒问题标注只保存在独立 feedback 表。先积累有人工**修改前后差异**的配对数据，再考虑 supervised fine-tuning / preference ranking。不得把“用户打 5 分”直接复制成每个 token 的真实标签；防止模型从自己的错误生成物中自我强化。评估反馈模型时也要按歌曲/版本隔离。
